Kubernetes

Deployment Manifest

A Kubernetes Deployment defines the desired state of the application running inside the cluster.

deployment.yaml Kubernetes 
apiVersion: apps/v1
kind: Deployment

metadata:
  name: cicd-demo

spec:
  replicas: 3

  selector:
    matchLabels:
      app: cicd-demo

  template:
    metadata:
      labels:
        app: cicd-demo

    spec:
      containers:

      - name: web
        image: registry.example.com/cicd-demo:v1.0.0

        ports:
        - containerPort: 8080

        readinessProbe:
          httpGet:
            path: /health
            port: 8080

        livenessProbe:
          httpGet:
            path: /health
            port: 8080
Operations

Useful Kubernetes Commands

Terminal kubectl 
# View Kubernetes nodes
kubectl get nodes

# View running pods
kubectl get pods -A

# Deploy application
kubectl apply -f deployment.yaml

# Check deployment status
kubectl rollout status deployment/cicd-demo

# View application logs
kubectl logs -f deployment/cicd-demo

# Scale application
kubectl scale deployment cicd-demo --replicas=5

# Roll back a failed release
kubectl rollout undo deployment/cicd-demo
Engineering Standards

CI/CD Best Practices

✓
Use immutable container images

Deploy versioned images instead of modifying running containers.

✓
Never deploy using the latest tag

Pin deployments to explicit application versions or image digests.

✓
Scan container images

Detect vulnerable libraries and operating-system packages before production deployment.

✓
Use readiness and liveness probes

Kubernetes should automatically identify unhealthy application instances.

✓
Use Git as the source of truth

Infrastructure and Kubernetes configuration should be version controlled and auditable.
